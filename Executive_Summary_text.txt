Executive Summary
This report analyzes the “42-image” price-action/ICT PDF and distills its key concepts into actionable model
features and integration plans. We identify each pattern or concept per page, then translate them into
numeric features (with detection algorithms, parameters, and data requirements). We propose a Feature
Extraction Layer that computes a rich set of features (binary flags and continuous measures) for use in
both LSTM and Random Forest (RF) models. We outline a new labeling strategy (ATR-based returns,
configurable prediction horizon) and class-balance methods. We map features to model usage (sequence vs
tabular models) and set target metrics. We also reference external sources (technical-analysis references
and code repositories) for similar feature ideas. An integration plan details new code modules
( order_block.py , bos_detector.py , etc.), data-pipeline changes, offline training procedure, and unit
tests. We provide example pseudocode for each detector and for assembling feature vectors. A prioritized
roadmap table estimates effort, risk, and expected impact on model accuracy/edge. Visual aids include a
Mermaid flowchart of the data pipeline, a comparison table of Mode A vs. Mode C features, and sample
charts (e.g. prediction confidence histogram). 
Overall, the report transforms the qualitative chart-pattern content into a quantitative decision-engine
feature layer. The aim is to endow the trading bot with “interpreted price-action” intelligence: recognizing
order blocks, breaks-of-structure (BOS), pullbacks, divergences, patterns (triangles, wedges, flags, etc.), and
candlestick signals, and encoding these as numeric features. This systematic approach allows machine-
learning models to leverage the underlying ideas in the PDF for more robust, explainable trade signals.

2. Feature Definitions & Detection Algorithms
Below we outline numeric feature definitions for each concept, including detection logic, required data,
parameters, and normalization ideas.
2.1 Order Blocks (Bullish/Bearish)
Definition: A price zone where “smart money” aggressed before a large move opposite. Typically
defined as the last bearish candle before a significant bullish break (Bullish OB) or the last bullish
candle before a big bearish move (Bearish OB). 
Features:
OB_High/Low: Price range of the identified candle (continuous). 
OB_Slope: Price move magnitude from OB to current (normalized change). 
Distance_to_OB: Distance from current price to OB zone (continuous). 
Within_OB: Binary flag if current price is inside the OB range (boolean). 
Algorithm Pseudocode:
# Identify Order Block: look for significant breakout 
if candle[t-1].close < candle[t-2].low and huge_bearish_move:

2.2 Break of Structure (BOS) / Change of Character (CHoCH)
Definition: A new swing high above the prior swing high (bullish BOS) or new swing low below prior
swing low (bearish BOS). CHoCH often defined as a lower high then a higher high (bullish CHoCH) in
ICT. 
Features:
BOS_Bull: Binary flag if a recent bullish BOS occurred. 
BOS_Bear: Binary if recent bearish BOS. 
BOS_Magnitude: Price move beyond last structure level (continuous, e.g. % above last high or % below
last low). 
Time_since_BOS: Bars since last BOS (normalized by session length). 
Algorithm Pseudocode:
last_swing_high = max(high[t-n : t-1])
if high[t] > last_swing_high:
BOS_bull = True
Inputs: Candles with clear swing high/low detection (peaks/valleys algorithm). 
Parameters: Lookback period to identify previous swing, minimum breakout size. 
Normalization: Express BOS move as fraction of ATR or previous range. Use time component (ratio
of bars/expected time).
2.3 Pullbacks
Definition: A retracement of price back toward a broken support/resistance or trendline before
continuation. 
Features:
Retraction_Size: Percent retracement from prior move (continuous). 
Distance_to_Line: Price distance from key trendline/support-resistance (normalized). 
Retrace_to_MA: Binary if price touched a moving average (e.g. 20 EMA) on retrace. 
Pullback_Low/High: Price extremum during pullback. 
Algorithm Pseudocode:
if price breaks support at t0:
find local high between t0 and t1 (retrace);
retrace_pct = (local_high - t0_price) / (t0_price - next_low)

2.4 Chart Patterns (Triangles, Wedges, Flags, Pennants)
For each pattern, features capture shape, angle, breakout direction, etc.
Ascending Triangle: Upper horizontal resistance, rising lows. 
Feat: Slope of support line, flatness of resistance. 
Detection: Identify >2 lower highs and ~horizontal highs (|Δhigh|<ε). 
Descending Triangle: Mirror (falling highs, flat support). 
Symmetrical Triangle: Converging trendlines. 
Broadening Wedge/Triangle: Diverging lines. 
Wedges (Rising/Falling): Two converging lines (rising wedge bearish, falling wedge bullish). 
Features: Slope ratio, height, breakout side. 
Flags/Pennants: Small consolidation after sharp move, usually parallel (flag) or small triangle
(pennant). 
Features: Flagpole height, consolidation duration, breakout momentum. 
Algorithm Pseudocode (generic pattern):
identify key swings (highs, lows) over lookback;
fit lines to highs and lows (linear regression);
measure line slopes and convergence;
pattern_detected = conditions on slopes and breakout.
Inputs: High/low series, possibly trendline fits. 
Parameters: Minimum pattern duration (bars), deviation tolerances (e.g. max gap between highs for
“flat”). 
Normalization: Express slopes as degrees or ratio of price change per bar. Pattern height/width
relative to ATR.
2.5 Multi-Peak Patterns (Double/Triple Top/Bottom, H&S)
Definition: Repeated highs or lows forming support/resistance zones. 
Features:
Top_Level: Price zone of the repeated high (mean of peaks). 
Bottom_Level: Price zone of repeated lows. 
Touches: Count of touches (≥2). 
Pattern_Duration: Time from first to last touch. 
Breakout: Price move beyond zone (flag true/false). 
Algorithm Pseudocode:
find price levels with multiple swings within small range (±δ);
if at least 2 peaks form a line, label double top.

2.6 Candlestick Patterns
Define features for various single/multi-candle patterns:
Hammer/Inverted Hammer: body small, long lower/upper wick, occurs in down/uptrend. 
Engulfing (Bull/Bear): Two-candle pattern where second engulfs first. 
Doji: open≈close (small body), signal indecision. 
Morning/Evening Star: Three-candle pattern: small “star” between big candle in opposite direction. 
Piercing Line/Dark Cloud Cover: Two-candle reversal patterns (second candles partially engulf
first). 
Three Soldiers/Crows: Three consecutive bullish/bearish candles of similar body. 
Features: For each pattern, binary flags. Also quantitative features like:
Body_to_Wick_Ratio, Candle_Longer_than_X%, Previous_Trend, etc.
Algorithm Pseudocode Example (Bullish Engulfing):
if candle[t-2].close < candle[t-2].open and candle[t-1].close >
candle[t-1].open and candle[t-1].open < candle[t-2].close and
candle[t-1].close > candle[t-2].open:
Bull_Engulfing = True
Inputs: OHLC candles. 
Parameters: Minimum body size, wick ratios (e.g. wick ≥ 2× body). 
Normalization: Candlestick features often binary, but we can quantify sizes relative to ATR or recent
candles.
2.7 Divergence (Oscillator)
Definition: Price makes higher high while RSI/ADX makes lower high (bearish divergence), or vice
versa. 
Features:
RSI_Value, RSI_Slope, RSI_Divergence_Flag; similarly MACD or Stochastic. 
Divergence_Type: none/regular/hidden (categorical). 
Algorithm Pseudocode:
if price[t] > price[t-k] and RSI[t] < RSI[t-k]:
bearish_divergence = True
Inputs: Price, RSI or other indicator values (calculated on candles). 
Parameters: Lookback lag k (e.g. 5 bars), threshold differences. 
Normalization: Divergence flagged as binary. Distance from divergence lines as continuous feature.

2.8 Volatility Compression
Definition: Squeezing of price range (low ATR or narrowing Bollinger Bands) often precedes
expansion. 
Features:
ATR, Bollinger_width, StdDev_narrow_flag. 
Vol_Std_Recent: Standard deviation of returns over window. 
Algorithm:
ATR = average(true_range, n)
compress = 1 if ATR < ATR_threshold else 0
Inputs: OHLC for ATR, possibly VWAP. 
Parameters: ATR lookback (e.g. 20), compression threshold (e.g. ATR < 0.5*meanATR). 
Normalization: ATR as fraction of price or scaled by moving average of ATR.

4. Model Mapping, Label Design & Metrics
Model Usage
LSTM (Sequence Model): Will consume sequential features (close prices, engineered features like 
ATR_20 , RSI, trend slopes, etc.) to capture temporal dependencies. Use continuous features (ATR,
RSI, slopes, distance-to-OB) and maybe also binned or normalized pattern flags. LSTM is suited to
features that evolve over time (e.g. moving average crossovers, oscillator trends, pattern formation
progress). 
Random Forest (Tabular): Will use “snapshots” of feature vectors at decision points. Good for binary
flags (pattern=1/0), static features (e.g. Volatility_Compress  flag, session one-hot). RF handles
heterogeneous features well. It may rely heavily on pattern flags and static measures, so features
like Engulf_Bull , OB_Flag , trendline break flags are useful here. 
Ensemble: Combine LSTM and RF outputs (e.g. average predicted return or quality score). LSTM’s
decision may favor trend and momentum features; RF may emphasize specific patterns and price-
level contexts.
Label Design
ATR-based Threshold: Use dynamic thresholds for labeling. For example, define 
threshold = 1.5 * ATR_20 . Label a BUY if future price change > +threshold, SELL if < -
threshold, otherwise hold. This filters out noise and ensures label reflects significant moves. (This
was approved by user in previous discussion.) 
FORWARD_CANDLES: Prediction horizon. For M5 data, likely N = 6–12  (30–60 minutes ahead) for
short-term moves. We recommend experimenting with 30m and 1h returns. The label uses the max
adverse or favorable excursion? (Simplest: future_return = close[t+N] - close[t] ). 
Class Balance: Expect many HOLD signals vs fewer decisive moves. After dropping hold, buy/sell
imbalance may occur. Use class weights or oversample underrepresented class. E.g., if BUY
significantly outnumbers SELL, apply class_weight  or SMOTE. (As noted in plan, weight inversely
to class frequency.) 
Target Metrics: Aim for overall accuracy ≥ 60–65% (since random ~50%), but more importantly high
precision on predicted signals. Use Win Rate (≥ 55% ideally) and PnL per trade, and look at 
confusion matrix focusing on false signals. For ensemble, expect accuracy ~60–70%. Maintain
quality score (signal confidence) improvement like in Mode C. 
Performance Targets: Ensure execution rate (trades taken) matches historical (no underfiltering).
Aim to increase mean return per trade and Sharpe ratio. Improvement in RSI/BOS/drawdown
metrics similar to Mode C audit (user’s prior context).

7. Integration Plan
New Modules:
order_block.py : Identifies bullish/bearish OBs using breakout logic. Exports OB ranges and
flags. 
bos_detector.py : Finds recent swing highs/lows, sets BOS and CHoCH flags. 
pattern_detector.py : Implements detection for triangles, wedges, flags, channels, etc. 
candles.py : Detects all candlestick patterns above, outputs binary flags and shape metrics. 
feature_layer.py : Orchestrates above modules, computes final feature vector per time-step,
normalizes values (ATR-scaling, etc.). 
Data Pipeline Changes:
Extend raw data with derived features: include volume (if available), RSI (14), ATR (20), trendline
endpoints, etc. 
Add sessions (NY/London/Asia) as dummy variables if needed (to segment patterns). 
Pre-compute fixed structures (like 20-EMA, Bollinger Bands) for pullback and squeeze detection. 
Training Pipeline Changes:
Move to offline training: new train_offline.py  using large historical window (≥1 year). 
Define train/val/test splits chronologically (e.g. 70/15/15%). 
Label generation uses ATR-based threshold and chosen horizon. 
Model persistence: save final model weights, use load_model()  at runtime (no retrain per loop). 
Regular validation: monitor accuracy (≥60%) and distribution of predictions (should not collapse to
0.5). 
Acceptance Tests:
Unit tests for each detector (feeding hand-crafted bar sequences, expect specific flags). E.g. input a
sequence with clear bull engulfing; test Engulf_Bull==1 . 
Integration test: synthetic data containing a known ascending triangle, ensure 
AscTriangle_Flag  is set. 
Check class-balance weights by inspecting training labels. 
Performance test: model inference on a held-out set yields balanced accuracy > threshold, minimal
drift.

Open Questions / Limitations
Exact Parameter Tuning: The thresholds (e.g. ATR multiplier, lookback lengths) need empirical
tuning on data. Our plan assumes initial guesses (ATR*1.5, 30–60m horizons) but will refine via
validation. 
Pattern Ambiguity: Many patterns overlap or form in noisy ways. Detectors may yield false
positives; classification should remain probabilistic. 
Data Sources: We assume availability of volume, multi-timeframe, and intra-session data. Limited
data could reduce feature effectiveness (e.g. missing session info). 
Despite these, the conversion of price-action content into a structured feature layer and robust training
procedure provides a clear path to significantly improving the model’s decision-making beyond mere signal
filtering.
